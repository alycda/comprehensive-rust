# Proposal: `.cheat` facilitator sheets for comprehensive-rust

Status: proposal only. Nothing created in the repo yet, nothing committed, nothing pushed.

## 1. How `cheat` resolves local sheets (verified against the cheat/cheat README)

- `cheat` walks up from the current working directory and adds the **nearest**
  `.cheat` directory it finds to the cheatpaths, temporarily. Only the nearest one.
- A sheet is an extension-less plain-text file named after the command used to
  view it: `cheat solution` reads `.cheat/solution`. Subdirectories give nested
  sheets: `cheat threads/scoped` reads `.cheat/threads/scoped`.
- Optional YAML frontmatter: `syntax:` (any Chroma lexer, e.g. `rust`, `bash`,
  `markdown`) and `tags:` (used by `cheat -l -t <tag>`).
- Flags confirmed in the README: `-l` list, `-s` search, `-t` tag filter,
  `-p` cheatpath filter, `-e` edit/create.

Consequences for layout:

- `cd src/types-and-values && cheat -l` shows only that segment's sheets. From
  `src/control-flow-basics/loops/` the walk-up finds
  `src/control-flow-basics/.cheat`. So one `.cheat` per top-level
  `src/<segment>/` is the right grain, and segments with nested slide folders
  (deep dives especially) use nested sheet paths inside that one `.cheat`.
- A repo-root `.cheat/` is only visible from the root and from directories that
  have no closer `.cheat`. If you want its sheets everywhere, register it once as
  a permanent cheatpath in `conf.yml`.

## 2. Layout

```
.cheat/                               # repo root, course-wide
  course                              # how these sheets work + clipboard one-liners
  setup                               # cargo xtask install-tools, mdbook serve, cargo xtask serve
src/<segment>/.cheat/
  outline                             # slides in order with minutes, exercise and solution timing
  exercise                            # starter code exactly as shown on the exercise slide
  solution                            # full solution from exercise.rs
  <slide-stem>                        # one per slide whose speaker notes ask you to modify code live
  cmds                                # only where the segment has shell commands
```

Naming rules:

- Sheet names mirror the slide file stems in `SUMMARY.md` (`variables`, `if`,
  `move`, `let-control-flow/if-let`), so the sheet name is the URL path you are
  already looking at.
- Generated sheets carry a first-line marker `GENERATED by tools/gen-cheats.py`
  so the generator can overwrite them and never touch hand-authored ones.
- Every sheet derived from course content keeps a one-line attribution naming
  the source file (exercise.rs is Apache-2.0, slides are CC-BY-4.0, both Google
  LLC). The fork is public, so attribution stays.

### 3.2 `exercise` (generated)

The starter code as the student sees it: `{{#include exercise.rs:anchor}}`
resolved, the hidden `# //` license lines dropped. For pasting into a fresh
`cargo new` when you solve live in an editor instead of the playground.

### 3.3 `solution` (generated)

`exercise.rs` with the license header and `ANCHOR` comment lines stripped.
Recommendation: whole file, not just the `solution` anchor, so the hidden tests
some exercises carry come along (you can drop a student's attempt in and
`cargo test` it). Example `src/control-flow-basics/.cheat/solution`:

```
---
syntax: rust
tags: [ comprehensive-rust, control-flow-basics, solution ]
---
// GENERATED by tools/gen-cheats.py from src/control-flow-basics/exercise.rs (Apache-2.0, Google LLC)
/// Determine the length of the collatz sequence beginning at `n`.
fn collatz_length(mut n: i32) -> u32 {
    let mut len = 1;
    while n > 1 {
        n = if n % 2 == 0 { n / 2 } else { 3 * n + 1 };
        len += 1;
    }
    len
}

fn main() {
    println!("Length: {}", collatz_length(11)); // should be 15
}

#[test]
fn test_collatz_length() {
    assert_eq!(collatz_length(11), 15);
}
```

### 3.4 Live-coding sheets, one per slide (hand-authored)

This is the part that addresses typing speed and spelling. The speaker notes
say things like "uncomment `x = 20`", "add `;` after `"small"`", "try making an
`&point.0` while `x_coord` is alive". The sheet gives the slide's code, then
each modification as a ready-to-paste line with the expected outcome.

Every variant will be compiled with the local `rustc` before the sheet is
written, so the stated error code is the real one, not a guess.

Example `src/control-flow-basics/.cheat/if`:

```
---
syntax: rust
tags: [ comprehensive-rust, control-flow-basics, live ]
---
// src/control-flow-basics/if.md (CC-BY-4.0, Google LLC)
fn main() {
    let x = 10;
    let size = if x < 20 { "small" } else { "large" };
    println!("number size: {}", size);
}

// LIVE 1: `;` after "small" -> E0308 `if` and `else` have incompatible types
    let size = if x < 20 { "small"; } else { "large" };

// LIVE 2: drop the `;` ending the let -> error: expected `;`, found `println`
    let size = if x < 20 { "small" } else { "large" }
    println!("number size: {}", size);
```

Example `src/types-and-values/.cheat/variables`:

```
---
syntax: rust
tags: [ comprehensive-rust, types-and-values, live ]
---
// src/types-and-values/variables.md (CC-BY-4.0, Google LLC)
fn main() {
    let x: i32 = 10;
    println!("x: {x}");
    // x = 20;
    // println!("x: {x}");
}

// LIVE 1: uncomment both lines -> E0384 cannot assign twice to immutable variable `x`
    x = 20;
    println!("x: {x}");

// LIVE 2: fix -> compiles, prints 10 then 20
    let mut x: i32 = 10;

// LIVE 3: keep `mut`, re-comment `x = 20` -> warning: variable does not need to be mutable
```

Example `src/references/.cheat/exclusive`:

```
---
syntax: rust
tags: [ comprehensive-rust, references, live ]
---
// src/references/exclusive.md (CC-BY-4.0, Google LLC)
fn main() {
    let mut point = (1, 2);
    let x_coord = &mut point.0;
    *x_coord = 20;
    println!("point: {point:?}");
}

// LIVE 1: shared borrow while x_coord alive -> E0502 cannot borrow `point.0` as immutable
    let x_coord = &mut point.0;
    let y = &point.0;
    *x_coord = 20;
    println!("{y}");

// LIVE 2: direct write while x_coord alive -> E0506 cannot assign to `point.0` because it is borrowed
    let x_coord = &mut point.0;
    point.0 = 5;
    *x_coord = 20;

// LIVE 3: contrast `let mut x_coord: &i32` (rebindable shared ref) vs `let x_coord: &mut i32`
```

## 4. Generator

`tools/gen-cheats.py`, Python stdlib only, run with `python3 -I`. Writes
`outline`, `exercise`, `solution` and the `src/exercises` code sheets. Skips any
file without the GENERATED marker. `--check` exits non-zero on drift so you can
re-run after pulling upstream.

Why a standalone script rather than `cargo xtask cheats`: the repo's convention
is xtask, but your fork pulls from google/comprehensive-rust and every edit to
`xtask/src/main.rs` or the workspace `members` list is a future merge conflict.
A new file in `tools/` conflicts with nothing. Rust instead of Python is fine
if you prefer; it costs a workspace member entry.

Live sheets and `cmds` are hand-authored and never touched by the generator.

## 5. Gotchas found

1. **mdbook copies the sheets into the built book.** mdbook-core's
   `copy_files_except_ext` copies every non-`.md` file under `src/` and has no
   dotfile filter. With `mdbook serve` the sheets are reachable at
   `localhost:3000/<segment>/.cheat/<name>`, and `publish.yml` would upload them
   to Pages. The solutions are already published on the solution pages, so this
   is cruft rather than a spoiler. If you publish the fork's Pages, add one step
   before `upload-pages-artifact`:
   `find book/html -type d -name .cheat -prune -exec rm -r {} +`.
2. `dprint fmt` matches by extension, so it ignores the sheets. Code inside
   generated sheets is already rustfmt-clean; live variants are intentionally
   broken and are left alone.
3. `cheat -e <name>` inside a temporary local cheatpath: the README does not say
   whether that path is writable. Test once after installing cheat.
4. `.gitignore` does not exclude `.cheat`, so the sheets commit with the repo.
   That matches your intent; say so if you want them ignored instead.

## 6. Decisions needed

1. Live sheets scope: Fundamentals only (73) for v1, deep dives on request?
   Recommendation: yes, unless you know which deep dives you are teaching.
2. Generator: yes/no, Python/Rust. Recommendation: yes, Python.
3. `solution` = whole exercise.rs including hidden tests (recommended) or only
   the `solution` anchor as the slide shows it.
4. publish.yml strip step: only if you deploy the fork's Pages.
5. Clipboard: `wl-copy`, `xclip -sel clip`, or `pbcopy` for the one-liners in
   the root `course` sheet.
